# 网站采集适配要求

这份文档用于交给其他 AI 或开发者，作为下一个商品网站适配爬虫时的固定要求。目标是只做网站适配，不重写采集框架，尽量沿用当前项目的数据结构、入库格式和运行方式。

## 1. 项目理解

- 先通读当前项目，理解主爬虫文件、采集框架、入库逻辑和已有字段格式。
- 不要随意改动采集框架核心逻辑，除非是为了处理反爬、运行稳定性或必要的站点适配。
- 网站适配重点包括：
  - 目录结构
  - 列表页商品链接
  - 翻页
  - 商品详情字段
  - 颜色/尺码变体
  - 图片
  - body 描述内容
  - 反爬和浏览器运行策略

## 2. 输出数据格式

输出字段参考当前项目 `goods` SQLite 表，常用字段如下：

```text
url
handle
more_info
title
subtitle
price
body
categories_1
categories_2
categories_3
option1_name
option1_value
option2_name
option2_value
option3_name
option3_value
image_src
size_price
sole_id
```

要求：

- 数据写入 SQLite 的 `goods` 表。
- `image_src` 如果是多图，保持列表格式，入库时可转 JSON 字符串。
- `option2_value` 尺码必须是列表字符串格式，例如：

```text
['18', '19', '20', '21']
```

- 同一个商品如果出现在不同目录下，需要允许按不同目录重复采集。
- 去重不能只按 URL 去重，建议按：

```text
categories_1 + categories_2 + categories_3 + url
```

生成 `sole_id`。

## 3. 目录采集要求

目录分析要多花时间，不能只抓表面导航。

要求：

- 需要采集完整、嵌套的目录名称和 URL。
- 最多保留三级目录：

```text
categories_1
categories_2
categories_3
```

- 目录格式参考当前项目 `payload_list` / `start_data` 的嵌套结构，例如：

```python
{
    "一级目录": {
        "二级目录": {
            "三级目录": "https://example.com/category"
        }
    }
}
```

- 只保留商品列表页。
- 避开无商品页、礼品卡、文章页、品牌介绍页、帮助页、会员页等采集不到商品的页面。
- 如果网站导航有一级、二级、三级目录，需要根据页面实际结构整理，不能只依赖面包屑。

## 4. 列表页要求

- 需要识别商品卡片链接选择器。
- 商品链接需要去重，但只在当前列表页内部去重。
- 不要因为一个商品在其他目录出现过就跳过。
- 必须实现翻页功能。
- 翻页方式需要根据站点实际判断：
  - `?p=2`
  - `?page=2`
  - 下一页按钮
  - 无限滚动
  - 接口分页

如果全量目录很多，不要一直只跑目录页。应优先或穿插处理商品详情，避免出现“缓存一直涨但 DB 没数据”的情况。

推荐调度策略：

```text
列表页抓到商品链接后，优先处理商品详情；
不要等所有目录和翻页跑完后才开始入库。
```

## 5. 商品详情字段

每个商品详情页至少采集：

- `url`
- `handle`
- `title`
- `price`
- `body`
- `categories_1`
- `categories_2`
- `categories_3`
- `option1_name`
- `option1_value`
- `option2_name`
- `option2_value`
- `image_src`

字段要求：

- `title` 必须干净，不带多余网站名、面包屑、营销文案。
- `price` 必须转为数字，例如 `64.95`。
- 必须校验核心字段，至少包括：
  - `title`
  - `price`
  - `image_src`
  - `handle`

## 6. 颜色变体要求

颜色变体非常重要。

要求：

- 商品如果有颜色变体，需要识别所有颜色变体 URL。
- 同一组颜色变体使用同一个 handle 前缀，不同颜色后缀递增：

```text
model00001_1
model00001_2
model00001_3
```

- 主商品和颜色变体都要入库。
- 如果网站没有明确颜色值，不要硬找。
- 没有明确颜色值时：

```text
option1_name = 目标语言里的“颜色”
option1_value = handle
```

例如荷兰语网站：

```text
option1_name = Kleur
option1_value = model00001_1
```

## 7. 尺码要求（不一定所有商品都有尺码，若没有可以不采集）

- `option2_name` 放尺码名称。
- `option2_value` 放所有尺码。
- 尺码必须采集完整，不区分是否售罄。
- 尺码格式必须是列表字符串：

```text
['18', '19', '20', '21']
```

不要只采集有库存尺码，要采集全部尺码。

## 8. Body 内容要求

body 需要采集商品描述和规格信息，并且要干净、可渲染。

要求：

- body 需要保留完整 HTML 元素，能被前端 HTML 渲染，需要你自己分析一下商品描述部分，需要采集的字眼包括但不限于商品详情，商品介绍，成分，使用方式...。
- 需要保留折叠/分区结构，或整理成可折叠区块。
- 需要去掉无用内容，例如：
  - `Meer informatie`
  - 分享按钮
  - script/style/svg
  - 多余按钮
  - 广告、推荐、配送说明等非商品正文内容

优先采集这些区块：

```text
Omschrijving / Description / 商品描述
Specificaties / Specifications / 商品规格
```

示例结构：

```html
<h2>Omschrijving</h2>
<div class="accordion__content" aria-expanded="false">
  ...
</div>
<h2>Specificaties</h2>
<div class="accordion__content" aria-expanded="false">
  ...
</div>
```

## 9. 图片要求

- 只采集当前商品详情页相关图片。
- 需要采集详情页所有商品图。
- 避免无关图片：
  - logo
  - icon
  - payment
  - trustpilot
  - size chart
  - meet system
  - placeholder
  - 相关推荐图

- 图片需要去重。
- 如果同一张图有多个尺寸，保留最大或质量最高的一张。
- 图片字段保留为列表，例如：

```python
[
    "https://example.com/image1.jpg",
    "https://example.com/image2.jpg"
]
```

## 10. 反爬与运行稳定性

如果网站有 Cloudflare、验证码、浏览器验证、403 或普通 requests 跑一会失效，不要长期依赖：

```text
requests + cookie
```

这种方式通常只能短时间有效。

优先使用真实浏览器上下文：

- Playwright CDP
- Botasaurus
- 持久化浏览器 profile
- `reuse_driver=True`
- 有头浏览器模式

经验：

- 如果 headless 过不了验证，必须使用有头模式。
- 浏览器可以最小化或放后台，但不能强行完全无浏览器。
- 全量跑时建议：

```text
headless = False
batch = 1
wait = 4~6 秒
reuse_driver = True
cache = True
```

如果浏览器能打开但代码跑一会又 403，说明不是选择器问题，而是反爬稳定性问题。

## 11. 缓存要求

建议开启 HTML 缓存：

- 列表页缓存
- 详情页缓存
- 颜色变体详情页缓存

缓存用途：

- 避免重复请求
- 避免 Cloudflare 频繁验证
- 出错后可以离线检查 HTML

注意：

- 不要缓存 Cloudflare challenge 页面。
- 不要缓存空页面。
- 缓存上涨不等于入库成功，需要同时观察 DB 记录数。

## 12. PyCharm 运行要求

尽量提供一个 PyCharm 可直接运行的入口文件，不依赖 PowerShell 环境变量。

入口文件应设置默认环境变量，例如：

```python
os.environ.setdefault("PYTHONUNBUFFERED", "1")
os.environ.setdefault("HEADLESS", "0")
os.environ.setdefault("BATCH", "1")
os.environ.setdefault("WAIT", "5")
```

并固定：

- 工作目录
- 输出 DB 目录
- 缓存目录

避免出现从 PowerShell 运行时 DB 写到：

```text
C:\Users\Administrator\goods
```

这种跑偏情况。

DB 应固定输出到项目目录，例如：

```text
项目目录\goods\时间戳_站点名.db
```

## 13. 调试验收

适配完成后先试跑小样本。

建议步骤：

1. 限制 1 个目录、1 页、1 条商品，验证能入库。
2. 再试跑 50 条数据。
3. 检查 DB 字段：
   - handle 是否按颜色变体递增
   - option1_value 是否符合要求
   - option2_value 是否是尺码列表字符串
   - body 是否干净
   - image_src 是否无重复无关图
   - 同商品不同目录是否能重复采集
4. 检查运行状态：
   - 缓存是否上涨
   - DB 是否同步增长
   - 是否一直卡在目录页
   - 是否出现 Cloudflare/403

如果代码一直运行但 DB 没数据，优先检查：

```text
1. 是否一直在跑列表/目录任务
2. 商品详情任务是否被优先消费
3. 详情解析是否返回空
4. DB 输出路径是否跑偏
5. 是否缓存了 challenge 页面
```
