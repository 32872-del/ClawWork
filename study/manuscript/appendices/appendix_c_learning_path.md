# 附录 C：推荐学习顺序与阶段验收

这本书的知识跨度很大，从 `requests.get()` 到分布式调度，从 HTML 解析到动态页面，从日志配置到平台化治理。新手如果一上来就跳到 JS 分析、浏览器指纹、Cloudflare 或验证码，很容易陷入“看起来很高级，但基础问题还没解决”的状态。

学习爬虫更像修路，不像跳远。你需要先能走通一条小路，再把路铺平，再加路灯、限速牌、收费站、监控和调度中心。每个阶段都有自己的目标，不必急着把所有技术一次学完。

## 1. 阶段一：先能抓到数据

对应章节：第 1 章到第 6 章。

这一阶段只解决一个问题：你能不能从一个明确的网页或接口里拿到目标数据。

需要掌握：

- 浏览器、服务器、HTTP 请求和响应的基本关系。
- URL、参数、请求头、编码的作用。
- `requests` 的基本用法。
- HTML 和 JSON 的区别。
- CSS 选择器、XPath、BeautifulSoup 或 lxml 的基本解析方式。
- 如何把结果打印、保存为 CSV。

阶段目标：

- 能写一个单文件脚本，请求一个静态页面。
- 能解析标题、链接、价格、发布时间等字段。
- 能请求一个 JSON 接口，并提取列表数据。
- 能解释为什么浏览器看到的内容和 HTML 源码可能不同。

验收任务：

1. 找一个自建或公开允许学习的静态页面。
2. 抓取列表标题和链接。
3. 保存到 CSV。
4. 对每个字段做空值检查。

常见误区：

- 只会复制代码，不知道 URL 参数是什么。
- 看到页面里有数据，就以为 `requests` 一定能抓到。
- 不区分 HTML、JSON、文本和二进制。
- 不设置超时，脚本卡住也不知道为什么。

## 2. 阶段二：把脚本变成稳定小工具

对应章节：第 7 章到第 13 章。

这一阶段的核心是“稳定”。一个脚本跑一次成功，不代表它能作为工具使用。工具需要处理分页、详情页、登录态、异常、重试、日志、配置、存储、去重和断点续爬。

需要掌握：

- 列表页到详情页的任务拆分。
- Cookie、Session、登录态的基本概念。
- 超时、重试、退避和限速。
- 日志记录和配置文件。
- CSV、SQLite、MySQL/PostgreSQL 的基本使用差异。
- 数据清洗、标准化、去重。
- 增量采集和断点续爬。

阶段目标：

- 程序失败后能知道失败在哪里。
- 重新运行不会重复写入大量脏数据。
- 能从上次进度继续，而不是每次从头开始。
- 配置能改，不需要每次改代码。

验收任务：

1. 写一个列表 + 详情采集器。
2. 支持 `config.yaml` 配置入口 URL、页数、延迟和输出路径。
3. 使用 SQLite 保存结果。
4. 给目标表加唯一键。
5. 支持中断后继续运行。
6. 日志里能看到成功数、失败数、重试数。

常见误区：

- 所有异常都 `except Exception: pass`。
- 重试没有上限。
- 失败不保存样本。
- 数据库没有唯一索引。
- 断点只存在内存里，程序退出就丢。

## 3. 阶段三：提升吞吐，但不牺牲秩序

对应章节：第 14 章到第 17 章。

当单线程太慢时，你会接触线程、进程、异步和 Scrapy。这个阶段最重要的不是“越快越好”，而是理解并发带来的副作用：更多失败、更难调试、更容易触发限速、更容易写入重复数据。

需要掌握：

- I/O 密集型和 CPU 密集型的区别。
- 线程池适合什么场景。
- `asyncio` 和 `aiohttp/httpx` 的基本模型。
- 并发数、QPS、连接池、超时的关系。
- Scrapy 的 Spider、Request、Response、Item、Pipeline、中间件。
- Scrapy 项目的目录结构和配置方式。

阶段目标：

- 能把任务队列和下载逻辑分开。
- 能控制并发，而不是任由程序疯狂请求。
- 能用 Scrapy 写一个标准项目。
- 能解释“并发数提高后为什么成功率反而下降”。

验收任务：

1. 用线程池改造一个详情页采集器。
2. 用异步写一个 JSON API 采集器。
3. 用 Scrapy 写一个列表 + 详情项目。
4. 对比三种写法的速度、日志和复杂度。

常见误区：

- 把并发当作性能问题的唯一答案。
- 没有全局限速。
- 多线程里共享同一个不安全对象。
- 异步函数里混入阻塞调用。
- Scrapy 项目里把所有逻辑都塞进 Spider。

## 4. 阶段四：处理动态页面和接口分析

对应章节：第 18 章到第 24 章。

动态页面不是“高级页面”，它只是数据到达浏览器的方式变复杂了。你要学会判断数据在哪里：在 HTML 里，在接口里，在脚本变量里，还是必须通过浏览器交互后才出现。

需要掌握：

- Network 面板的基本使用。
- XHR/fetch 接口识别。
- Playwright 的基本打开、点击、等待、截图、提取。
- 接口参数来源分析。
- 常见时间戳、分页游标、签名字段的概念。
- JavaScript 可读性整理和调试。
- AST 的基本概念：代码也可以被解析成树。

阶段目标：

- 能判断一个页面该用 `requests`、接口，还是 Playwright。
- 能从 Network 面板找到真实数据接口。
- 能写一个稳定的 Playwright 小任务。
- 能读懂简单 JavaScript 参数生成逻辑。
- 能理解 AST 在代码转换和分析中的作用。

验收任务：

1. 找一个自建动态页面，数据通过 XHR 返回。
2. 先用 Playwright 抓页面，再用 Network 分析接口。
3. 改成直接请求接口。
4. 写一段简单 JS 参数生成函数，并用 Python 或 Node 调用。

常见误区：

- 所有动态页面都上浏览器，成本过高。
- 只会 `sleep`，不会等待元素或响应。
- 复制请求头时带入大量无用缓存头。
- 把混淆、压缩、模块化都混为一谈。
- 只追求跑通，不记录分析过程。

## 5. 阶段五：理解风控、指纹和访问治理

对应章节：第 25 章到第 31 章。

这一阶段要特别注意边界。本书讨论浏览器指纹、验证码、行为风控、Cloudflare 和代理治理，是为了让你理解现代 Web 系统如何保护自己，以及授权采集系统如何降低扰动、提升可审计性。不要把这些主题理解成“绕过第三方防护”的技巧集合。

需要掌握：

- 浏览器环境由哪些信号组成。
- 为什么自动化环境和真实用户环境会不同。
- 验证码为什么出现。
- 行为风控一般会看哪些宏观信号。
- Cloudflare 等安全网关在系统中的位置。
- 代理的质量、稳定性、信誉和合规风险。
- 礼貌采集、限额、配额和访问治理。

阶段目标：

- 能在授权靶场里观察不同环境的差异。
- 能解释为什么频率、账号、出口、行为都会影响风险评分。
- 能为企业采集任务设计限速、审计和暂停机制。
- 能在遇到验证码或安全拦截时做合规决策。

验收任务：

1. 自建一个页面，记录 User-Agent、语言、时区、窗口尺寸等环境信号。
2. 用普通浏览器和自动化浏览器访问，对比差异。
3. 设计一份采集任务合规检查清单。
4. 给采集系统增加“连续风险事件自动暂停”规则。

常见误区：

- 只盯技术绕法，不看授权边界。
- 把代理数量当成系统质量。
- 忽略账号和数据权限。
- 没有审计日志。
- 触发验证码后仍继续自动请求。

## 6. 阶段六：分布式、平台化和团队协作

对应章节：第 32 章到第 40 章。

当采集任务越来越多，系统就不再是“一个脚本”，而是“一个平台”。平台要关心任务调度、队列、状态、权限、监控、告警、配置、密钥、测试、维护和交接。

需要掌握：

- Redis 队列和去重集合。
- 任务拆分、状态流转和失败重试。
- 分布式 worker 的幂等设计。
- 平台应提供哪些能力。
- 指标、日志、告警、SLO。
- 配置、密钥和权限管理。
- 解析器测试、样本回放、页面改版维护。
- 交接文档和运行手册。

阶段目标：

- 能把单机任务拆成队列 + worker。
- 能看懂采集平台的核心模块。
- 能为任务设置监控和告警。
- 能写出别人接手得了的文档。

验收任务：

1. 用 Redis 实现一个任务队列。
2. 启动两个 worker 消费同一队列。
3. 使用唯一键保证重复任务不会重复入库。
4. 给任务增加运行指标。
5. 写一份交接文档。

常见误区：

- 队列里只有 URL，没有任务上下文。
- 失败任务无限重试。
- 没有死信队列。
- 配置和密钥混在代码里。
- 系统只有作者本人会用。

## 7. 阶段七：综合项目串联

对应内容：综合项目 A-G。

综合项目不是为了重复章节知识，而是把知识放到接近真实工作的环境里。建议按顺序完成：

- 项目 A：静态站点采集，巩固 HTTP、解析、CSV。
- 项目 B：JSON API 采集，巩固接口、分页、数据库。
- 项目 C：动态页面采集，巩固 Playwright 和接口分析。
- 项目 D：Redis 分布式采集，巩固队列、worker、幂等。
- 项目 E：授权风控信号实验室，巩固风险理解和审计。
- 项目 F：采集平台 MVP，巩固平台化思维。
- 项目 G：真实商品网站适配案例，巩固目录、列表、详情、变体、缓存、入库、断点和小样本验收。

每做完一个项目，都建议写一页复盘：

- 哪个环节最容易出错。
- 哪些日志帮你定位了问题。
- 哪些代码可以复用。
- 如果数据量扩大 10 倍，哪里会先出问题。
- 如果交给别人维护，需要补什么文档。

## 8. 不同背景读者的路线建议

### 完全小白

先完整读第 1 到第 13 章，不要跳。每一章都自己敲示例，哪怕代码很短。你最需要的是建立直觉：请求是什么、响应是什么、字段从哪里来、错误怎么查。

### 会 Python，但没做过爬虫

可以快速浏览第 1 到第 2 章，从第 3 章开始动手。重点放在第 7 到第 13 章，因为工程稳定性往往比语法更难。

### 做过脚本，想进阶工程化

重点读第 14 到第 17 章、第 32 到第 40 章。你需要从“写脚本”转向“设计系统”：队列、幂等、监控、配置、交接。

### 主要处理动态页面

重点读第 18 到第 24 章，但不要跳过第 9、10、12、13 章。动态页面更需要日志、样本、清洗和断点，否则问题会更难排查。

### 负责企业合规采集

重点读第 25 到第 31 章、第 35 到第 40 章。你要关注授权、审计、频率、配额、暂停机制、账号权限和团队协作。

## 9. 最小作品集建议

学完整本书后，建议至少保留 4 个作品：

1. 一个静态页面采集器。
2. 一个 JSON API 增量采集器。
3. 一个 Playwright 动态页面采集器。
4. 一个 Redis 队列 worker 示例。

每个作品都要有 README、配置示例、运行命令、数据表结构、日志示例和常见问题。作品集不是为了炫技，而是证明你能把采集任务做完整。

## 10. 自检清单

如果你能回答下面的问题，说明你已经不是只会“复制爬虫代码”的阶段了：

- 一个请求失败时，我应该先看哪些信息？
- 为什么状态码 200 仍可能是失败？
- 什么情况下应该用接口，什么情况下才用浏览器自动化？
- 为什么重试必须有上限？
- 为什么数据库唯一键比代码里的去重集合更可靠？
- 什么是幂等？
- 为什么并发提高可能导致成功率下降？
- 为什么验证码出现后应该暂停而不是继续冲？
- 一个采集任务交给同事维护，需要哪些文档？
- 如果目标页面改版，我怎么快速确认影响范围？
